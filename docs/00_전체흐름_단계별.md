# 전체 흐름 — 파이프라인 A / B / C / D

이 브랜치의 코드는 네 갈래로 나뉜다. 다이어그램은 [40_분석_기록/PROJECT_ANALYSIS.md](40_분석_기록/PROJECT_ANALYSIS.md) §2 의 것을 지금 경로에 맞춰 다시 그렸다. 진입점은 대부분 루트의 `run_steps.py` 다.

| 갈래 | 목적 | 진입점 | 결과물 |
| --- | --- | --- | --- |
| A 실시간 | 키포인트 → 서버 → 뷰어 | `python run_steps.py --server` | 브라우저 3패널 뷰어 |
| B 학습 | 2D→3D 리프터 학습 | `python run_steps.py --train` | `model_3d/artifacts/checkpoints/*.pt`, 지표 json, 곡선 png |
| C Unity 내보내기 | 3D 라벨 → Unity JSON | `python run_steps.py --export-unity` | `artifacts/unity_fitness_viewer/sequences/` |
| D 오프라인 분석 | 피터 비교·QA | `python -m model_3d --check-all` | `model_3d/artifacts/pose_debug/`, `model_3d_check_all.json` |

`run_steps.py --step N` 은 아래 8단계 설명을 찍어 준다. 실제로 일을 하는 단계는 1(입력 확인), 2(영상 → `video_client`), 4(체크포인트로 `--dummy` 검증), 8(서버 시작)뿐이다. 3·5·6·7 은 "서버 안에 통합되어 있다"는 안내만 출력한다.

```text
Step 1 데이터 준비   Step 2 포즈 추정(MoveNet/MediaPipe)   Step 3 정규화
Step 4 3D 리프팅 + 스무딩   Step 5 DTW 비교   Step 6 점수   Step 7 피드백   Step 8 UI
```

> Step 5(DTW)·6(점수)은 `run_steps.py` 의 설명에만 있고, 이 브랜치 서버에는 DTW 비교 코드가 없다. 서버 점수는 자리표시자다([30_실시간_서버/01_서버와_2D뷰어.md](30_실시간_서버/01_서버와_2D뷰어.md)). DTW 기반 비교는 [App 브랜치](https://github.com/logan0741/VR-Based-Real-Time-Agent/tree/App)에서 구현되었다.

## A. 실시간 파이프라인

```text
┌─────────────────────────────────────────────────────────────────┐
│                    Pipeline A: Real-time                        │
│                                                                 │
│  [Client]                     [Server]               [Viewer]   │
│                                                                 │
│  clients/webcam_client.py ──┐                                   │
│  clients/video_client.py  ──┤                                   │
│  clients/dataset_client.py──┼─WebSocket─→ server_app/server.py  │
│  tools/play_squat.py      ──┤             ├─ PoseLifterNet (MLP)│
│  viewer_2d (브라우저 MoveNet)┘             ├─ PoseRetargeter     │
│                                           ├─ PostureAnalyzer    │
│                                           └─WebSocket→ viewer_2d│
└─────────────────────────────────────────────────────────────────┘
```

1. 클라이언트가 COCO-17 키포인트 17×3 을 `/ws/pose` 로 보낸다.
2. 서버가 `PoseLifterNet` 으로 global_orient(3) + body_pose(63) 를 낸다. **단, 배포 체크포인트의 가중치는 실제로 실리지 않는다** — [20_학습/02_SMPLX_피팅과_좌표계.md](20_학습/02_SMPLX_피팅과_좌표계.md).
3. `PoseRetargeter` 가 속도 제한 → OneEuro 필터로 프레임 간 떨림을 줄인다.
4. `PostureAnalyzer` 가 2D 입력의 관절 각도로 근육 피로도를 판정한다.
5. 응답을 연결된 모든 클라이언트에 브로드캐스트한다 → 2D 뷰어가 그린다.

`FITTER_BACKEND=optimization` 이면 2번 대신 SMPL-X 최적화 피터(`fitter.py`)가 돈다 (문서상 ≈540 ms/frame).

## C. Unity 내보내기 파이프라인

```text
┌─────────────────────────────────────────────────────────────────┐
│                    Pipeline C: Unity Export                     │
│                                                                 │
│  피트니스 라벨 (2D + 3D JSON)                                   │
│         │                                                       │
│         ▼                                                       │
│  model_3d/export_fitness_unity.py                              │
│  ├─ Root reference (골반 기준점)                                │
│  ├─ Ground offset (바닥면 보정)                                 │
│  ├─ 좌표계 → Unity Y-up, --units-per-meter 100 (cm → m)        │
│  └─ Bone links                                                 │
│         │                                                       │
│         ▼                                                       │
│  artifacts/unity_fitness_viewer/sequences/                      │
│  └─ train/D05-1-001_view1.json (시퀀스별 JSON)                  │
└─────────────────────────────────────────────────────────────────┘
```

- `--limit` 기본값은 split 당 3개다. 전체는 `--limit 0` (`run_steps.py --export-unity` 가 그렇게 부른다). 문서상 전체 내보내기 결과는 240 시퀀스다 ([model_3d_deep_analysis.md](40_분석_기록/model_3d_deep_analysis.md)).
- 이것을 재생하던 Unity 스캐폴드(`unity/FitnessPoseViewer/`)는 이 브랜치에서 지웠다. 원본은 docs-archive 브랜치에 있다.

## D. 오프라인 분석 파이프라인

```text
┌─────────────────────────────────────────────────────────────────┐
│                    Pipeline D: Offline Analysis                 │
│                                                                 │
│  입력: 키포인트 JSON / pose_3d_v3 / SMPL-X 좌표                 │
│         │                                                       │
│         ▼                                                       │
│  pipeline_cli.py (--check-all / --input / --pose3d-path)       │
│  ├─ DummyFitter (파이프라인 배선 테스트)                         │
│  ├─ DirectPose3DFitter (3D 라벨 직접 사용)                       │
│  ├─ PoseLifterFitter (학습된 MLP)                               │
│  ├─ SMPLXCoordinateFitter (3D 좌표 → SMPL-X 최적화)             │
│  └─ OptimizationPoseFitter (2D 리프로젝션 → SMPL-X)             │
│         │                                                       │
│         ▼                                                       │
│  PosePipeline.process_keypoints()                              │
│  ├─ Fitter.forward() → FitResult (3D 관절, 2D 투영)             │
│  ├─ analyze_squat() → SquatFeedback (무릎각, 라벨)               │
│  └─ DiagnosticsRecorder.record() → QA 이미지/그래프             │
│         │                                                       │
│         ▼                                                       │
│  model_3d/artifacts/pose_debug/<세션>/                          │
│  ├─ frames/*.png   ├─ graphs/performance_graph.png             │
│  └─ metrics.jsonl                                               │
└─────────────────────────────────────────────────────────────────┘
```

| 명령 | 하는 일 |
| --- | --- |
| `python -m model_3d` | 인자 없음 → `--check-all`, 결과를 `model_3d/artifacts/model_3d_check_all.json` 에 덮어씀 |
| `python -m model_3d --dummy` | SMPL-X 없이 배선·진단만 |
| `python model_3d/run_pipeline.py --input data_samples/sample_keypoints.json --output result.json` | 키포인트 1프레임 → 기본 피터 (SMPL-X 최적화, 모델 파일 필요) |
| `python model_3d/run_pipeline.py --lifter-checkpoint <pt> --input data_samples/sample_keypoints.json` | 같은 입력을 MLP 로 |
| `python model_3d/run_pipeline.py --pose3d-path pose_3d_v3 --max-frames 3` | 3D 라벨을 그대로 분석 |
| `python model_3d/run_pipeline.py --smplx-fit-pose3d --pose3d-path pose_3d_v3 --max-frames 1` | 3D 좌표 → SMPL-X 피팅 실현 가능성 |

결과 해석은 루트 [README.md](../README.md) §E.
