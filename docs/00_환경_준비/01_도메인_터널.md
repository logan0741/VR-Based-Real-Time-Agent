# 도메인·터널 — Cloudflare Tunnel 로 폰과 Quest 붙이기

> **이 문서의 `gun-hee.com` 과 그 하위 호스트는 작성자 개인 도메인이다.** 그대로 따라 하면 작성자 서버로 붙거나 아무 데도 안 붙는다. 읽는 사람은 자기 Cloudflare 계정의 도메인으로 모두 바꿔야 한다. 아래에서 `<내도메인>` 으로 적은 곳이 그 자리다.

## 왜 터널이 필요한가

- 폰 viewer 는 `localhost`·`127.0.0.1` 이 아니면 **HTTPS 에서만** 카메라를 연다. `http://<PC_IP>:8000/viewer/` 로 열면 `Camera requires HTTPS on this address…` 에러가 뜬다(`viewer.js` 의 `needsHttps`).
- 그래서 폰은 HTTPS 주소가 필요하고, 작성자는 PC 의 `localhost:8000` 을 Cloudflare Tunnel 로 내보냈다.

## 작성자 구성 (실제로 쓴 것)

| 호스트 | 브라우저에서 여는 주소 | 서버 동작 |
|---|---|---|
| `viewer.gun-hee.com` | `https://viewer.gun-hee.com/viewer/` | `/` 로 오면 `/viewer/` 로 리다이렉트 |
| `app.gun-hee.com` | `https://app.gun-hee.com/app/` | `/` 로 오면 `/app/` 로 리다이렉트 |
| `pt.gun-hee.com` | `https://pt.gun-hee.com/api/health` | API 와 공유 WebSocket `wss://pt.gun-hee.com/ws/pose` |

세 호스트 모두 같은 서버 프로세스(`http://localhost:8000`)로 간다. 호스트별 리다이렉트는 `server.py` 의 `@app.get("/")` 가 `Host` 헤더 앞부분(`viewer.`, `app.`, `pt.`)을 보고 한다.

## 1. cloudflared 설정 파일

작성자 PC 의 `%USERPROFILE%\.cloudflared\config.yml` 에서 ingress 부분만 옮긴다(터널 ID·자격증명 줄은 각자 것으로).

```yaml
tunnel: <터널 ID>
credentials-file: C:\Users\<사용자>\.cloudflared\<터널 ID>.json

ingress:
  - hostname: pt.<내도메인>
    service: http://localhost:8000
  - hostname: viewer.<내도메인>
    service: http://localhost:8000
  - hostname: app.<내도메인>
    service: http://localhost:8000
  - service: http_status:404
```

터널 만들기·DNS 연결은 Cloudflare 공식 절차(`cloudflared tunnel login` → `cloudflared tunnel create <이름>` → 호스트마다 `cloudflared tunnel route dns <이름> <호스트>`)를 따른다. 이 저장소에는 터널 생성 스크립트가 없다.

## 2. 실행

```powershell
# 창 1: 서버
.\.venv\Scripts\Activate.ps1
.\final\scripts\00_pipeline.ps1

# 창 2: 터널
cloudflared tunnel run <이름>
```

확인: `https://pt.<내도메인>/api/health` 가 `{"status":"ok", …}` 를 돌려주면 터널이 붙은 것이다.

## 3. 두 페이지가 WebSocket 호스트 하나를 함께 써야 하는 이유

앱에서 운동을 고르면 앱은 `session_config` 를 WS 로 보내고, 서버는 그것을 **같은 서버의 모든 WS 연결**에 방송한다. 폰 viewer 가 그 방송을 받아야 전문가 포즈를 같은 운동으로 바꾼다.

예전 viewer 는 자기 페이지 호스트로 WS 주소를 계산해서 `wss://viewer.gun-hee.com/ws/pose` 로 붙었고, 도메인에서 WS 가 끊기는 문제가 있었다([FINAL_ARCHITECTURE.md](../../final/FINAL_ARCHITECTURE.md) "WebSocket Disconnect On Domain"). 그래서 지금은 두 페이지 모두 `pt.` 호스트 하나를 쓴다.

| 파일 | 위치 | 내용 |
|---|---|---|
| `final/s05_frontend/viewer.js` | `window.addEventListener("load", …)` 안 | `location.hostname.endsWith("gun-hee.com")` 이면 `wss://pt.gun-hee.com/ws/pose` |
| `final/src/hooks/useWebSocket.ts` | `buildWsUrl()` | `window.location.hostname.endsWith('gun-hee.com')` 이면 `wss://pt.gun-hee.com/ws/pose` |
| `final/latency_lab/run_latency_suite.py` | `--cloud-url` 기본값 | `wss://pt.gun-hee.com/ws/pose` |

**자기 도메인으로 바꿀 때**: 위 세 곳의 `gun-hee.com` 을 `<내도메인>` 으로 고치고 `npm --prefix final run build` 로 앱을 다시 빌드한다(`useWebSocket.ts` 는 빌드 결과 `final/app_dist` 에 들어가야 반영된다). viewer 는 빌드 없이 바로 반영된다(서버가 `viewer.js` 를 캐시 없이 서빙). 지연 측정은 코드를 고치는 대신 `--cloud-url wss://pt.<내도메인>/ws/pose` 를 넘겨도 된다.

도메인이 아닌 주소(`localhost`, LAN IP)에서는 두 파일 모두 페이지 호스트의 8000 번 포트로 WS 를 만든다.

## 4. CSP — MoveNet 모델 주소 허용

서버는 `/viewer/` 응답에 Content-Security-Policy 를 붙인다(`server.py` 의 `NoCacheMiddleware`). TF.js 와 MoveNet 모델은 외부에서 받아 오므로 `connect-src` 에 그 주소가 모두 있어야 한다. 예전에는 Kaggle 쪽 리다이렉트 주소가 빠져 모델 fetch 가 막혔고, 카메라는 켜졌는데 관절점이 하나도 안 나왔다.

현재 허용 목록:

```text
script-src  'self' https://cdn.jsdelivr.net 'unsafe-eval' 'wasm-unsafe-eval'
connect-src 'self' ws: wss: https://cdn.jsdelivr.net https://tfhub.dev
            https://storage.googleapis.com https://www.kaggle.com https://kaggle.com
```

viewer 가 불러오는 스크립트는 `tfjs@4.17.0`, `pose-detection@2.1.3` (jsDelivr) 이다. 모델 호스팅 주소가 또 바뀌면 브라우저 콘솔의 CSP 위반 메시지에 찍힌 주소를 `connect-src` 에 더한다.
