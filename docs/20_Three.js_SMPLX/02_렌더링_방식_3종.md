# 렌더링 방식 3종 (V1 / V2 / V3) — "방식 비교" 화면

2026-06-08, PSVR 3D 웹앱(지금의 [`app_3d_web/`](../../app_3d_web/))에 "방식 비교" 버튼을 달고 전문가 스쿼트 한 시퀀스를 세 가지 렌더러로 나란히 돌렸다. 화면 제목은 "렌더링 방식 비교 (전문가 스쿼트)" 이다.

> [!NOTE]
> 세 컴포넌트(`Skeleton3DCanvas.tsx`, `Skeleton3DCanvasV2.tsx`, `SkeletonWireframe3D.tsx`)와 훅은 남아 있지만, **"방식 비교" 페이지를 조립하던 `App.tsx` 버전은 어느 브랜치에도 커밋되지 않았다.** 이 브랜치의 `app_3d_web/src/App.tsx` 는 2D 버전(`SkeletonCanvas2D`)이며 세 컴포넌트를 import 하지 않는다. 화면은 [스크린샷](../30_스크린샷/README.md)으로만 남았다.

## V1 — SMPL-X MLP 파라미터로 FBX 뼈 회전

- FBX 를 `clone(true)` 한 뒤 SkinnedMesh 의 skeleton 을 복제 뼈로 다시 bind 한다(같은 FBX 로 강사·사용자 두 체를 띄우기 위함).
- 뼈 이름 exact match 로 SMPL-X 22관절(`pelvis` … `right_wrist`)을 찾고 rest 쿼터니언을 저장한다(실험 1의 수정).
- 프레임마다 `rest × quatFromRodrigues(body_pose[i*3..i*3+2])` 를 목표로 `SLERP_FACTOR = 0.18` 만큼 따라간다. `framesRef` 가 있으면 `fps`(기본 8) 기준으로 두 키프레임을 선형 보간해 루프 재생한다.
- 축 변환은 `src/utils/smplMath.ts` 의 `(rx, −ry, −rz)` — Unity `SMPLX.cs` 의 `QuatFromRodrigues`(axis `(−rx, ry, rz)`, angle `−θ`)와 동치(실험 4).
- **틀린 이유는 렌더러가 아니라 입력**: 서버 MLP 의 66차원 출력이 올바른 SMPL-X local 회전이 아니다(실험 3·5).

## V2 — 3D 관절 좌표로 기하 IK

- 로드 시 6개 뼈(좌우 hip→knee, knee→ankle, shoulder→elbow)의 rest 방향 `D_rest` 와 rest world 쿼터니언을 읽는다. 팔꿈치→손목은 "손목이 너무 자유롭게 움직인다"는 이유로 제외.
- 프레임마다 `Q_delta = setFromUnitVectors(D_rest, D_actual)`, `Q_new_world = Q_delta × Q_rest_world`, `Q_new_local = inv(parent_world) × Q_new_world`, `SLERP = 0.35`.
- 좌표 변환: 이 스냅샷 코드는 **MotionBERT-Lite 좌표(x=right, y=down, z=depth) → `(x, −y, z)`** 를 쓴다. 6월 8일 마지막 시점에 `/api/expert-pose3d` 가 MotionBERT-Lite 결과(`squat_expert_keypoints_3d_mb.json`)를 내도록 바뀌었기 때문이다(서버 코드 기준).
- **PoseLifterMLP 출력**(013 라벨로 학습)은 라벨 좌표계 그대로 **Y-up · cm** 다: `pt[1]`=높이, `pt[0]`=좌우, `pt[2]`=깊이 (2026-10-12 체크포인트 출력 48개 확인: 코 pt1≈159 > 어깨 144 > 엉덩이 94 > 무릎 62 > 발목 25). Three.js 도 Y-up 이므로 축 교환 없이 cm→m 스케일과 골반 원점 이동만 하면 된다. 상세는 Pose3D 브랜치 `docs/20_학습/02_SMPLX_피팅과_좌표계.md` §4.
- 참고: [실험 로그](01_실험_로그_2026-06-08.md) §5·실험 7 의 "x=깊이, y=좌우, z=높이 → `[y→X, z→Y, x→Z]`" 와, 이후 세션 메모의 "`pt[2]`=높이 → `(pt[0], pt[2], −pt[1])`" 는 둘 다 위 측정과 맞지 않는다 — 커밋된 어느 경로도 그런 값을 내지 않아 다른 입력 공간을 본 것으로 추정한다(로그는 역사 기록이라 원문 유지). 어떤 소스든 렌더러에 넣기 전에 코·발목 높이 축을 직접 확인할 것.
- 실패 원인(실험 7): 부모 world 회전이 그 프레임에 갱신되지 않은 값을 쓰는 문제, local/world 혼동.

스크린샷: v2check 0s/3s/7s/11s 가운데 패널(팔 하나만 내려간 자세, 11s 에 무릎 굽힘), 이후 `osctest`·`frame160`·`debug`·`v2_skelutils*` 가운데 패널(T-pose 정지, osctest 에는 디버그용 빨간 상자).

## V3 — 와이어프레임

- COCO-17 관절 17개를 구로, 14개 연결(팔·몸통·다리·머리-어깨)을 선으로 그린다. FBX·IK 없음.
- 골반 중심을 원점으로 빼고 `(x, −y, z)`, `SCALE = 1.0`(MotionBERT 출력이 대략 미터 단위). PoseLifterMLP 출력(Y-up, cm)을 쓰려면 축 교환 없이 cm→m 스케일과 골반 원점 이동이 필요하다.
- 관절 좌표가 정상이면 정상으로 보인다 — 다만 3D 좌표의 정확도는 실험 6 의 "MPJPE 10.87mm" 가 아니라 **약 10.9 cm** 다(라벨이 cm 단위, 로그의 mm 표기는 오기). 관절당 10 cm 오차는 와이어프레임엔 보이지만 메시 아바타를 세우기엔 거칠다.

스크린샷: 모든 `web3d_render_methods_*` 의 오른쪽 패널.
