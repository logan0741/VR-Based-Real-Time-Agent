# 좌표 규약

한 줄 요약: **어디서나 COCO-17 `[y, x, confidence]`, 0~1 정규화. 변환은 그리는 순간에만 한다.**

## 1. 기본 형식

- 관절 17 개, COCO 순서(0 코, 1·2 눈, 3·4 귀, 5·6 어깨, 7·8 팔꿈치, 9·10 손목, 11·12 엉덩이, 13·14 무릎, 15·16 발목. 홀수가 왼쪽). 인덱스 상수는 `final/s01_preprocessing/utils/keypoints.py`.
- 각 관절은 `[y, x, confidence]` — **y 가 먼저**다. MoveNet 출력 순서를 따른 것이다.
- y·x 는 영상 높이·너비로 나눈 0~1 값이다. y 는 아래로 갈수록 커진다.
- 서버는 17 개가 아니거나 숫자가 아닌 payload 를 거부한다(`_validate_keypoints`).

## 2. viewer 에서 만드는 법

```javascript
// final/s05_frontend/viewer.js
const payload = poses[0].keypoints.map(kp => [kp.y / vh, kp.x / vw, kp.score ?? 0.9]);
```

TF.js MoveNet 은 픽셀 좌표를 주므로 비디오 크기로 나눈다. 이 `payload` 가 그대로 서버로 간다.

## 3. 폰 세로 회전은 viewer 로컬 전용

- 폰이 세로인데 카메라 스트림이 가로(`videoHeight < videoWidth`)로 오면, 미리보기 뼈대가 옆으로 누워 보인다.
- viewer 는 이때 `correctMobilePortraitPayload` 로 원본·시계방향·반시계방향 세 후보 중 "머리가 위, 다리가 아래, 세로로 긴" 것을 골라 **미리보기용 사본(`displayPayload`)만** 회전한다.
- WebSocket 으로 보내는 값은 회전하지 않은 원본 `payload` 다. 그래서 앱·점수·횟수는 viewer UI 수정의 영향을 받지 않는다.
- 이 규칙을 깨고 회전된 값을 서버로 보내면 정규화·횟수 각도가 모두 틀어진다.

## 4. 좌우 반전은 그릴 때만

- 앱의 `좌우 반전` 버튼은 `SkeletonCanvas2D` 의 `mirror` prop 만 바꾼다. `normalizeToCanvas` 가 캔버스 x 를 `canvasW - x` 로 뒤집는다.
- 서버로 가는 값, 서버가 계산하는 값은 반전되지 않는다.

## 5. 전문가 `.npy` — 정규화된 것과 픽셀 단위가 섞여 있다

- `final/assets/expert_videos/*.npy` 는 모두 `[y, x, confidence]` 순서지만, 어떤 파일은 0~1 이고 어떤 파일은 픽셀 단위다. 예: `/api/expert?exercise=pull_up` 은 `pull_up.npy` 의 첫 관절을 `[245.37, 961.21, 0.9]` 처럼 픽셀 값으로 돌려준다(2026-10-12 확인).
- 그래서 앱(`SkeletonCanvas2D.tsx` `normalizeToCanvas`)은 그리기 전에 형식을 판별한다.
  - 값이 모두 대략 0~1 이면(`allNorm`) 코의 0 번 열 값이 발목보다 작은지로 `[y, x]` 인지 본다.
  - 픽셀 단위면 0 번 열이 "코 < 발목" 이고 0 번 열의 범위가 1 번 열보다 5 % 이상 넓을 때 `[y, x]` 로 본다.
  - 판별 후 관절 범위를 캔버스에 맞춰 가운데 정렬·확대한다(여백 10 %).
- viewer 도 전문가 포즈를 그리기 전에 같은 취지로 0 번 열이 세로축처럼 움직이는지 확인한다. 이 판별 덕분에 데스크톱·폰 모두에서 전문가 포즈가 서 있다.
- 서버의 DTW 는 `.npy` 의 정규화 시퀀스(`sequence`)를 쓰고, 화면용 `/api/expert` 는 `raw_sequence` 를 먼저 돌려준다.

## 6. 하지 말 것

1. `[x, y]` 순서로 바꿔 저장하거나 보내지 않는다.
2. 서버·전처리 쪽에서 반전·회전하지 않는다.
3. 전문가 캐시를 새로 만들면 형식(정규화/픽셀)을 섞어도 되지만 순서는 반드시 `[y, x, confidence]` 로 둔다.
