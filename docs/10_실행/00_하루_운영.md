# 하루 운영 — 켜기부터 끄기까지

설치는 끝났다고 본다([../00_환경_준비/00_처음_시작.md](../00_환경_준비/00_처음_시작.md)). 폰·Quest 를 HTTPS 도메인으로 붙인다면 터널 설정도 끝나 있어야 한다([../00_환경_준비/01_도메인_터널.md](../00_환경_준비/01_도메인_터널.md)). 아래 `<내도메인>` 은 자기 도메인이다(작성자는 `gun-hee.com`).

## 준비물

- PC (서버), 스마트폰 (카메라, 전신이 보이게 세워 둘 거치대), Meta Quest 3 (브라우저)
- 운동별 촬영 방향: 스쿼트·해머 컬은 옆모습(`view: "side"`, `normalizer_type: "side_left"`), 레터럴 레이즈·풀업은 정면(`view: "front"`) 기준이다(`final/s01_preprocessing/config.py`). 옆모습 운동은 왼쪽 엉덩이·어깨를 기준 관절로 정규화하고(`side_left`), 해머 컬은 왼팔(어깨·팔꿈치·손목)만 판정에 쓴다. 그래서 몸 왼쪽이 카메라에 보이게 서는 편이 맞다 — 코드에서 끌어낸 권장이고, 좌우를 바꿔 비교 측정한 기록은 없다.

## 1. 서버 켜기

```powershell
cd <저장소 루트>
.\.venv\Scripts\Activate.ps1
.\final\scripts\00_pipeline.ps1          # 검증 + 빌드 + 서버 (0.0.0.0:8000)
```

- 빌드를 건너뛰려면 `.\final\scripts\00_pipeline.ps1 -SkipVerify` (빌드만 하고 py_compile 은 건너뜀) 또는 `.\final\scripts\03_run_server.ps1` (바로 서버).
- 포트를 바꾸려면 `-Port 8001`. 단 앱·viewer 는 도메인이 아닐 때 8000 을 가정한다(`useWebSocket.ts`, `viewer.js`).
- 도메인을 쓰면 다른 창에서 `cloudflared tunnel run <이름>`.
- 확인: `curl.exe http://127.0.0.1:8000/api/health` → `{"status":"ok", …}`

## 2. 폰에서 viewer 열고 카메라 허용

1. 폰 브라우저로 `https://viewer.<내도메인>/viewer/` 를 연다.
2. 0.5 초 뒤 WebSocket 이 자동으로 붙는다(`Connect` 버튼으로 다시 붙일 수 있다). 주소 칸은 도메인이면 `wss://pt.<내도메인>/ws/pose` 로 자동으로 바뀐다.
3. `📷 웹캠 시작` → 카메라 권한 허용. 전면 카메라(`facingMode: "user"`)를 쓴다.
4. 상태 줄에 `detect N / send N / ws open / last 0s …` 가 늘어나고 내 뼈대가 그려지면 정상이다.
5. 폰을 세워 **전신이 화면 안에 다 들어오게** 둔다. 운동에 쓰는 관절이 가장자리에 닿거나 흐리면 그 프레임은 점수·횟수에서 빠진다.

## 3. Quest 에서 app 열기

1. Quest 3 브라우저로 `https://app.<내도메인>/app/` 를 연다. (같은 Wi-Fi 의 `http://<PC_IP>:8000/app/` 도 앱 자체는 열리지만, 이 조합은 문서 작성 시 다시 확인하지 않았다.)
2. 첫 화면에 `PSvR`, 운동 4 개, `세트 수`, `세트당 횟수`, `운동 시작` 이 보인다.

## 4. 운동 선택 · 세트 · 횟수

1. 운동을 고른다: 스쿼트 / 해머 컬 / 레터럴 레이즈 / 풀업. 고르는 순간 폰 viewer 의 전문가 포즈가 그 운동으로 바뀐다(앱 `session_config` → 서버 방송 → viewer).
2. `세트 수`(기본 3, 1~10)와 `세트당 횟수`(기본 8, 1~50)를 `-`/`+` 로 정한다.
3. `운동 시작`. 앱이 `session_start` 를 보내고 운동 화면으로 넘어간다.
4. 운동 화면에서 보는 것: 강사 모델(전문가 포즈), 내 자세(빨간 관절 = 서버 `bad_joints`), 점수, 현재 세트·세트 내 횟수, 피드백 문장, 경과 시간.
5. 내 자세가 거울처럼 보이길 원하면 `좌우 반전` 버튼. 그리기만 뒤집고 서버로 가는 값은 그대로다.

## 5. 종료 · 최종 리포트 · TTS

1. 서버가 센 총 횟수가 `세트 수 × 세트당 횟수` 에 닿으면(`completed: true`) 앱이 자동으로 종료한다. 중간에 끝내려면 `운동 종료`. 두 경우 모두 같은 `handleEndSession` 이 돈다.
2. 앱이 서버에 `session_end` 를 보낸다. `DB_ENABLED=true` 이고 연결돼 있으면 이때 세션 요약이 MySQL `exercise_sessions` 에 저장된다.
3. 결과 화면: 평균 점수, 등급, 총 횟수, 운동 시간(분), 자세 정확도, `최종 자세 분석`(운동 중 `feedback_event=true` 로 쌓인 샘플의 결정적 집계).
4. 결과 화면이 뜨면 앱이 `/api/tts/final-feedback` 을 자동으로 부른다. 서버 PC 에서 pyttsx3 가 `final/assets/tts/final_feedback_<해시>.wav` 를 만들고, 앱이 `/assets/tts/…` 로 받아 재생한다. 브라우저가 자동 재생을 막으면 `음성이 준비되었습니다. … 재생 버튼을 누르세요.` 가 뜬다 → 재생 버튼을 누른다.
5. 결과 화면 아래에 `운동 중 주요 피드백`(최근 4 개)이 있고, `다시 시작`·`처음으로` 버튼은 둘 다 첫 화면으로 돌아간다.

## 6. 서버 끄기

- 서버 창에서 `Ctrl+C`. 터널 창도 `Ctrl+C`.
- 창을 그냥 닫아 프로세스가 남으면 다음 실행에서 8000 포트가 막힌다 → [01_트러블슈팅.md](01_트러블슈팅.md) 1 번.
- 생성된 TTS `.wav` 는 `.gitignore` 대상이라 지우지 않아도 커밋에 섞이지 않는다.

## 7. 지연 측정 돌리기

서버를 켠 상태에서 다른 창에서:

```powershell
.\.venv\Scripts\Activate.ps1
.\final\scripts\04_latency_check.ps1
```

- 내용: `python final\latency_lab\run_latency_suite.py --frames 90 --fps 30 --exercise squat`. 로컬 `ws://127.0.0.1:8000/ws/pose` 를 먼저, Cloudflare `wss://pt.gun-hee.com/ws/pose` 를 다음에 잰다.
- 자기 도메인이면 직접 부른다: `python final\latency_lab\run_latency_suite.py --cloud-url wss://pt.<내도메인>/ws/pose`
- 터널이 없으면 로컬 보고서만 저장되고 Cloudflare 단계에서 연결 에러로 끝난다. 로컬만 잴 때는 `python final\latency_lab\measure_latency.py --ws-url ws://127.0.0.1:8000/ws/pose --label local`.
- 결과는 `final/latency_lab/results/` 의 커밋된 파일을 덮어쓴다. 기존 기준값을 남기고 싶으면 돌리기 전에 복사해 둔다.
- 측정 소켓도 서버 입장에서는 일반 클라이언트라서, 앱·viewer 가 붙어 있으면 측정 중 `session_config` 가 그쪽에도 방송된다. 측정은 실제 운동이 없을 때 돌린다.
