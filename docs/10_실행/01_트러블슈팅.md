## 1. 포트 8000 이 이미 쓰이는 중

증상: `ERROR: [Errno 10048] error while attempting to bind on address ('0.0.0.0', 8000)` 류로 uvicorn 이 바로 끝난다.

```powershell
netstat -ano | findstr :8000          # 맨 끝 숫자가 PID
taskkill /F /PID <PID>
```

창을 닫아도 python 프로세스가 남는 경우가 있다. 끌 때는 서버 창에서 `Ctrl+C` 를 쓴다.

## 2. dtaidistance

- 설치: 최신 버전은 `pyproject.toml` 스펙 충돌로 빌드가 실패한 적이 있다. `final/requirements.txt` 가 `dtaidistance==2.3.12` 로 고정하는 이유다. 따로 깔 때도 `pip install dtaidistance==2.3.12`.
- 증상: 설치가 안 된 채 서버가 뜨면 import 실패를 잡아서 계속 돈다. 로그 맨 앞에 `[Pipeline] dtaidistance … pip install dtaidistance==2.3.12` 가 찍히고, DTW·`ScoreEngine` 이 빠져 점수가 기본값 50(또는 피로도 기반 값)으로만 나온다. 횟수·피드백 문장은 계속 나오므로 놓치기 쉽다.
- 확인: `python -c "import dtaidistance"`

## 3. Python 3.8 타입 힌트

- 증상: `TypeError: 'type' object is not subscriptable` (`list[tuple]`, `dict[str, …]` 등 3.9+ 문법을 3.8 에서 평가할 때).
- 해결: 파일 맨 위에 `from __future__ import annotations` 를 둔다. 전처리·TTS 모듈에는 이미 들어 있다. 새 파일을 만들거나 `server.py` 처럼 이 줄이 없는 파일의 **모듈 수준 시그니처**에 새 문법을 쓰면 다시 터진다.

## 4. 폰에서 카메라가 안 켜진다

- 원인: 브라우저는 보안 컨텍스트(HTTPS 또는 localhost)에서만 카메라를 준다. viewer 는 이를 미리 검사해 `Camera requires HTTPS on this address. Open the viewer with an HTTPS URL, not http://…` 를 띄운다.
- 해결: 폰은 `https://viewer.<내도메인>/viewer/` 로 연다 → [../00_환경_준비/01_도메인_터널.md](../00_환경_준비/01_도메인_터널.md).

## 5. MoveNet 모델 fetch 가 CSP 에 막힘

- 증상: 카메라 화면은 나오는데 뼈대가 없고, 상태 줄의 `detect` 가 늘지 않는다. FPS 숫자는 높게 보일 수 있다. 브라우저 콘솔에 CSP 위반(`Refused to connect to …`).
- 원인: viewer CSP 의 `connect-src` 에 Kaggle 쪽 모델 리다이렉트 주소가 없었다.
- 해결(반영됨): `server.py` `NoCacheMiddleware` 의 `connect-src` 에 jsDelivr, TFHub, Google Storage, Kaggle(`www.kaggle.com`, `kaggle.com`)을 허용했다. 모델 주소가 또 바뀌면 콘솔에 찍힌 주소를 더한다.

## 6. 앱과 viewer 의 WebSocket 호스트

- 증상: 도메인에서 viewer WS 가 끊긴다. 앱에서 운동을 바꿔도 폰 전문가 포즈가 이전 운동으로 남는다.
- 원인: viewer 가 자기 페이지 호스트로 `wss://viewer.gun-hee.com/ws/pose` 를 만들었다. 운동 선택 방송은 같은 서버의 WS 연결로만 간다.
- 해결(반영됨): `*.gun-hee.com` 페이지는 viewer·app 모두 `wss://pt.gun-hee.com/ws/pose` 를 쓴다(`viewer.js` load 핸들러, `useWebSocket.ts` `buildWsUrl`). 자기 도메인으로 바꿀 때 이 두 곳을 같이 고치고 앱을 다시 빌드한다. 하나만 고치면 이 증상이 그대로 돌아온다.
- 보조: viewer 는 1 초마다 `/api/session-control` 도 폴링하므로 WS 방송을 놓쳐도 결국 따라간다. 그래도 안 바뀌면 viewer 페이지를 새로 고친다.

## 7. 앱 뼈대가 끊기고 늦다

- 원인 ①: 실시간 뼈대가 피드백 계산 결과에 묶여 있어서, 점수·피드백 계산이 늦으면 뼈대도 늦었다.
- 해결(반영됨): relay 경로를 분리했다. 서버는 keypoints 를 받자마자 `data_type: "pose"` 로 방송하고, 피드백은 최신 프레임만 따로 계산한다. **두 경로를 다시 합치지 않는다**(FINAL_ARCHITECTURE 개발 규칙 1).
- 원인 ②: 전체 시퀀스 DTW 를 매 프레임 돌리면 비싸다.
- 해결(반영됨): `dtw_interval`(3 프레임마다), 짧은 실시간 창(`n_frames`), 처리 중 들어온 프레임은 최신 하나만 남기기. 더 줄이려면 `.env` 의 `DTW_INTERVAL_OVERRIDE`, `DTW_N_FRAMES_OVERRIDE`, `DTW_EXPERT_STRIDE` 를 쓴다.
- 확인: 로컬에서 앱 relay 평균이 수 ms 인데 도메인에서 200 ms 대라면 서버가 아니라 네트워크 구간 문제다 → [../30_지연_측정/01_측정_방법과_결과.md](../30_지연_측정/01_측정_방법과_결과.md).

## 8. 실시간 피드백이 안 나온다 / 카메라 안내만 계속 뜬다

- 원인 ①(버그): 카메라 가시성 게이트가 운동 설정에 없는 `confidence_joints` 를 읽었다.
- 해결(반영됨): 게이트는 운동별 `keypoints_used` 를 쓴다.
- 원인 ②: 게이트 기준이 너무 엄격했다(처음 `camera_quality_feedback_v1` 은 confidence `0.25`, 가장자리 `0.02`).
- 해결(반영됨): 기본값을 `CAMERA_MIN_CONFIDENCE=0.12`, `CAMERA_EDGE_MARGIN=0.01` 로 낮췄다. 더 바꾸려면 **셸 환경 변수**로 준다(`.env` 로는 안 바뀐다 — import 시점에 읽힌다).
- 그래도 계속 안내가 뜨면: 그 운동의 판정 관절이 실제로 화면 안에 있는지 본다. 해머 컬은 왼팔, 레터럴 레이즈·풀업은 양어깨·양팔꿈치, 스쿼트는 양어깨·엉덩이·무릎·발목이다.
- 문장이 3 초가량 같은 내용으로 고정되는 것은 정상이다(피드백 hold).

## 9. 좌표 회귀 — 뼈대가 눕거나 뒤집힘

- 원인: 예전 viewer 파일이 실수로 최종 viewer 위에 복사됐다.
- 해결(반영됨): 최종 viewer 로직을 되살리고 도메인 WS 주소 수정만 남겼다.
- 지킬 것: 좌표는 `[y, x, confidence]`, 좌우 반전은 그릴 때만, 폰 세로 회전은 viewer 미리보기에만 → [../20_판정_규칙/01_좌표_규약.md](../20_판정_규칙/01_좌표_규약.md). viewer 를 고친 뒤 화면이 이상하면 브라우저 캐시보다 파일 자체를 먼저 의심한다(서버는 `/viewer/` 를 `no-cache` 로 준다).

## 10. PowerShell 실행 정책

- 증상: `…ps1 파일을 로드할 수 없습니다. 이 시스템에서 스크립트를 실행할 수 없으므로…`
- 해결: 그 창에서만 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` 후 다시 실행한다.
